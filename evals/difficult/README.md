# 原始材料困难评测

与 `evals/evals.json` 的十一项基础行为回归分别维护。原题保留；本目录增加独立原始文件、完整章节任务和评分条件，避免只靠题干复述规则。现有题干信息充分不能据此认定“标准答案泄漏”。

## 材料与对照

| 案例 | 原始输入 | 任务 | 首轮重复 |
| --- | --- | --- | --- |
| repair-dispatch | 十份合成源码、SQL、配置、旧文档及两类版本/单位报告 | 从材料发现实现，写五节完整章与依据映射 | 每条件两次 |
| inventory-transfer | 十份合成源码、配置、SQL、旧章及两批次报告 | 引用原稿段落审查并修订完整章，保留正确机制 | 每条件一次 |

两题均为与既有校园报名题不同的项目，不是实际业务项目或真实测试报告，也不是保密的外部标准题。候选规则冻结后再运行，结果用于小样本诊断，不能推出跨项目普遍效果。首轮没有验证约二十模块或跨会话接续，这些属于后续批次。

四个条件是无任务技能、原项目通用规范摘录、冻结的 0.3.0、候选改进版。**原规范对照是通用段落摘录，不是原项目完整工作流。**提取范围、当前版本提交和文件指纹在 `baselines/provenance.json`；项目专属事实、模块与学校字数要求不移植进留出题。

所有运行使用同一父会话继承的模型与推理配置，不覆盖单次设置；当前接口没有公开具体模型标识，报告应保留这一限制。每次从全新上下文开始，任务与工具约束相同，随机排列运行顺序，不从多个输出中挑最好的一份。

## 输入与评分分开

`cases/<case>/input/` 只放作者给定的原始材料与用户任务；`grading/` 放评分事实及判据；运行副本只包含 `input/`、分配的 `rules/` 和公共运行说明。条件映射与哈希放在副本之外，输出另存。

```text
python evals/difficult/prepare.py --case repair-dispatch --condition current --output "<新的运行目录>" --metadata "<运行目录外的私有记录.json>"
```

脚本不调用模型、不联网，不覆盖已有运行或身份记录，不复制评分。输入副本设为只读，记录哈希；运行代理被要求只读指定材料、不加载全局技能、不读其他运行/评分、不执行项目代码，只写本次 `output.md`。这是副本隔离、只读标志和指令约束，**不是操作系统级读取沙箱**。需要强隔离的评测应在相应宿主中限制工具可读范围，不能将此脚本说成已实现该能力。

## 评分与保留结果

- 评分代理另开新上下文，只得到案例原始材料、独立评分条件及重新编号的匿名输出，不提供条件映射或规则文件。
- 事实错误与深度分开。深度的适用项按缺失/仅提及/机制充分记录，并引用输出段落或短摘录；不适用、证据不足或无法评定另记，不以字数/关键词替代判断。
- 关键事实错误列出原句和来源，不能用高深度分抵消。跨版本、批次和单位分别比较。
- 保留全部原始输出、匿名评分、映射、来源指纹及复核更正。汇报逐案例、逐条件的失败与重复波动；双方都能完成时写“未显示增益”。小样本不做未经支持的显著性或排名结论。
- 若数据或规则在看到输出后修改，应另开轮次并保留旧结果；不能把已调试的案例继续叫未接触的留出题。

评测资产与评分不装入技能发行 ZIP，以免把评估目标混入日常运行规则。运行本目录的检查需要完整仓库：

```text
python -B -m unittest discover -s evals/difficult -p test_*.py -v
```

初始化、发行检查通过只说明脚本与打包行为；模型章节质量以实际输出和对应审查记录为依据。
