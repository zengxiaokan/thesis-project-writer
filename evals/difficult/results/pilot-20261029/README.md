# 第一批实测：未显示候选规则的相对增益

日期：2026-10-29。此次完成两种合成项目、四种规则条件、共十二次独立写作和两次匿名代理评审。**在本次模型配置、题目及量表下，候选版相对 0.3.0 和无技能条件未显示增益。**四种条件都能完成所给章节；新增规则、对照样例和脚本不能据此宣传为已证明提高论文质量。

## 设计与实际执行

| 条件 | 实际提供的规则 |
| --- | --- |
| none | 不加载任务技能；基础平台指令及同一公共文件范围约束仍存在 |
| original | 原项目质量标准 §2、§3 和写作规范选段的通用段落；排除专属事实/模块/学校篇幅，不是完整原工作流 |
| current | 冻结的 0.3.0，源提交 `31b34cc28a50e8cf5b6f58dad0bbdfcadf7741a1` |
| candidate | 增加按章深度指南及完整章对照的候选规则；运行前冻结，不根据本轮答案修改 |

维修派工题每条件运行两次，库房调拨题每条件一次。每次写作和每个评分任务均从新上下文开始，写作调用继承同一父会话配置，不做单次模型/推理设置覆盖。接口未公开具体模型标识，因此记录的是“同一继承配置”，不是经模型 ID 独立核验的跨模型实验。顺序以种子 20261029 随机排列。

current 与 candidate 的运行规则包含技能入口、参考文本及写作示例的 Markdown/JSON，未提供初始化/图表执行程序及渲染附件；本轮只比较指定章节任务，不是完整技能安装或全部工具能力对照。

运行副本仅含本题原始材料、对应规则及公共运行说明；评分与身份映射另存，禁止加载全局技能。输入设只读并记录哈希，十二份运行的输入/规则指纹均复核一致。此处是副本和指令范围约束，**没有操作系统级读取隔离**，也没有独立的全工具读取审计，不能把它宣称为强沙箱。

匿名评分任务只收到原始输入、评分条件和重新编号的稿件，不提供规则条件/身份映射。评分来自独立代理，不是人类盲评；同一模型家族作答与评分可能共享偏差。全部原稿按字节保留，未挑最好稿件、未重写失败输出。评分原始响应与最终响应均保存，未做评分修改；摘要工具只检查摘录、结构、原稿哈希并汇总已有判断，不自动判定语义质量。

## 观察结果

“深度”是六个适用项各 0/1/2 的合计，最高12；它不是论文总分。关键错误单独列示，不能由深度抵消。

| 规则条件 | 派工题：次数；深度均值及范围 | 派工题：含关键错误的稿数 | 调拨题：次数；深度 | 调拨题：关键错误 | 其他已记录问题 |
| --- | --- | --- | --- | --- | --- |
| none | 2；12（12—12） | 0/2 | 1；12 | 0/1 | 0 |
| original | 2；12（12—12） | 0/2 | 1；12 | 0/1 | 1处非关键事实不准确 |
| current | 2；12（12—12） | 0/2 | 1；12 | 0/1 | 0 |
| candidate | 2；12（12—12） | 0/2 | 1；12 | 0/1 | 0 |

派工的重复运行在本量表上没有分数波动；原始文字仍不同，两次重复不足以证明稳定性。调拨每条件仅一次，不能估计运行波动或把一个细节差异当成系统性优势。所有输出都在量表高端，说明本题/本配置出现天花板，区分度不足；不能把“未检出关键错误”解释为所有事实、文风与长篇质量均已验收。

实际发现的非关键错误位于 [B03](outputs/B03.md) 的 P10 审查：“两个耗时的单位、测量对象和版本也不同。”两份输入报告的 `timing.unit` 都是 `seconds`，真正不同的是人工端到端观察与一次服务调用、版本和条件。该稿后文没有据此推出性能提升，故评分将其记在其他问题，未列为关键错误。主代理回查两份原始 JSON 确认了这一点，原稿未被悄悄修正。

深度判据具有可检查产物：[B04](outputs/B04.md) 对原稿 P04 的事务概述区分“事实有依据”和“数据/事务关系仅提及”，再补写源库存扣减与调拨记录共同提交、插入失败的回滚边界。它展示了候选规则所要求的审查方式，但其他条件也完成了同类机制解释，不能据此单独认定质量增益。教学用的[设备借还章节对照](../../../../examples/chapter-depth/README.md)另列事实正确的浅稿与展开稿，亦不作为本次模型效果分数。
