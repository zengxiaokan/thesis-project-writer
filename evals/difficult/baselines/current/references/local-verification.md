# 本地验证与真实截图

本指南是运行时的工作步骤，不是一个已经替任意项目配置好的通用测试器。项目的服务、账号、用例、数据库和工具需要从当前环境识别。

先复用 [environment-and-fallbacks.md](environment-and-fallbacks.md) 所记能力和缺口，只验证尚未测试的有关目标。专用工具、已有本地自动化与用户真实记录可以是不同执行路径，必须分别保留来源；打开页面、截图可见或工具名出现都不代表业务断言已验证。

## 准备与启动

1. 从项目 README、包管理脚本、构建文件、容器配置及测试配置找启动方式，确认前后端、数据库、缓存和外部依赖。引用配置键和脱敏值，不将密码、令牌、连接密钥复制到论文材料。
2. 优先复用现有本地实例，检查地址、健康状态和实际数据环境；localhost 不能证明连接的是测试数据库。启动服务前确认不会运行破坏性迁移、重置数据或指向生产资源。
3. 用户要求本地测试和截图时，可启动必要服务、使用已有测试账号，创建可清理的隔离测试数据；已有授权不重复确认。涉及删除真实数据、外部发送、真实支付或收费调用且无授权时，只暂停相关步骤并问具体必要信息，继续其他可执行工作。
4. 按当前环境可用工具选择浏览器连接或自动化工具，先读取其指引；优先复用项目测试设施。需要编写浏览器脚本时可使用 Playwright 等实际已安装工具，缺少时说明可用替代方式，不假定工具永远存在。
5. 后台服务在 Windows 中使用隐藏窗口，记录由本轮启动的进程或会话，完成后按需要关闭；不要停止用户原来启动的服务。

## 先用例，再操作与截图

按真实项目选一条核心业务主线，并覆盖必要角色、关键状态、失败输入、权限与资源归属边界。测试表写“编号、关联需求/证据、前置条件、操作、预期、实际、状态、批次/附件”。预期结果先确定，运行后再填写实际结果，不能用观察结果反推预期制造通过。

以界面状态、接口响应或持久化结果验证相应断言；截图是辅助记录。按本轮范围运行相关单元/集成测试或构建，保留命令、时间、退出码和原始报告位置，不因仓库有测试文件就写成已执行。

没有隔离数据或测试账号时，继续只读页面、构建或其他不依赖它们的工作，将写入用例记为阻塞。真实失败写失败，未执行写未执行；修复需得到本轮开发范围授权后进行，重新验证才记录修复后通过。论文任务本身不授权为了截图修改业务逻辑。

## 截图归档

只采集真实启动后的页面，禁止用生成图、静态 HTML 重绘或改 DOM 伪造实现。演示数据须标明为测试数据。选择能说明业务的稳定页面，检查加载完成、弹窗、遮挡、文字可读性及敏感信息，先采集再实际查看图片。

截图放 `resources/screenshots/<批次>/`，原图和论文用图分别保留。允许等比裁剪和必要脱敏，记录处理，不改业务状态或结果。涉及个人信息时优先使用测试数据；需要脱敏时使用可用且适合的图像工具，不因工具限制泄露数据。

截图索引记录文件、采集时间、页面/本地地址、角色、场景、关联用例、对应章节、观察、是否裁剪/脱敏和原图路径。账号仅使用角色或匿名标识，地址中的令牌要去除。

## 报告与边界

每批次保存环境、工作区基线、数据准备、实际步骤、断言、通过/失败/阻塞/未执行数量及附件。统计来自本批次逐项记录，不能合并重复运行来凑覆盖率。性能记录需有负载参数、持续时间、样本量和原始输出；短时本地结果不推导生产容量或长期稳定性。缺少性能测试不妨碍如实报告功能测试。

后续写测试章时把本批次条件集中说明，并给每个具体数字保留必要适用范围。构建、浏览器观察、自动化用例和性能测试分开报告。
