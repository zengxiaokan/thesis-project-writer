# 论文图表：从主张到可交付图片

用于图表规划、技术制图、数据绘图、表格编排或已有图表修改。图表应回答正文中的具体问题，来源可以回查，图源可以编辑，导出可以复现。图的数量由论证需要决定，不按“每章至少几张”凑图。

## 接入六阶段

- 第一阶段盘点已有图、图源、数据、界面截图与代码/SQL来源，区分实际实现、设计方案和计划功能；已有图并非已核实。
- 第二阶段只补图表会影响定位或交付的缺口，如学校图表规范、用户指定工具和可取得的数据，不增设固定制图问卷。
- 第三阶段在章节蓝图中规划图表，用 `figures/index.md` 或已有同职能清单登记用途、章节、图种、来源与缺口。此时可画明确标为草案的结构示意，不能把拟补关系当已实现事实。
- 第四阶段核对来源、提取节点/连线或数据，再实际生成、导出和查看；缺关键关系或数值时先补证据。记录所用工具、版本或生成方式与材料基线。
- 第五阶段核对图、表、正文的术语、步骤、关系和数字；正文解释图说明什么及为何有意义，不只写“如下图所示”。
- 第六阶段统一正式图号/表号、题注、正文引用、清单与导出版本；插入正式稿后按实际尺寸渲染检查，记录本轮实际验收范围。

只修改一张已有图时直接读取该图、有关正文和来源，不重跑全量分析、访谈或完整初始化。保留原图及正确内容，来源变化时只复核受影响图表及正文。已有学校正式图号和格式优先沿用。

## 选什么图，依据是什么

| 图表 | 用于解释 | 必须核对的内容 |
| --- | --- | --- |
| 架构/模块图 | 职责、分层和连接 | 区分逻辑架构、代码模块和真实部署；源码目录不等于独立运行服务，规划组件须显式标记 |
| 业务/程序流程图 | 操作、处理与判断路径 | 回查真实入口、顺序、条件、成功及相关失败出口；判断边标条件，重要循环/异常不因简化而消失 |
| 时序图 | 角色/组件之间的调用 | 调用方、被调方、先后、参数或消息、返回与失败；不自行添加鉴权、异步、缓存、重试或外部服务 |
| 状态图 | 状态及允许的迁移 | 区分持久状态与临时步骤；迁移条件、触发者、终态和禁止路径有代码/规则依据 |
| ER/数据关系图 | 实体、表和数据关系 | 说明概念/逻辑/物理层次；主键、外键、可空性、基数和唯一性来自实际材料，不能由命名推断物理约束 |
| 用例图 | 角色可完成的目标 | 角色、系统边界、用例及关系；不把页面按钮逐个当用例，也不补未实现功能 |
| 统计图 | 真数据中的比较、变化或分布 | 类别/时间顺序、单位、样本/批次、分母、聚合方式和真实值；选择适合问题的柱/折线/散点等图种 |
| 数据表/比较表 | 字段、需求、用例、结果或来源比较 | 表头、单位、数据来源、主键/状态等含义、缺失值与口径；优先提供可编辑表格，避免将表格截图作为唯一交付 |

ER 图中，代码中的关联不等于 SQL 已声明外键；外键定义不证明运行库已启用或迁移已执行。组合唯一约束不能画成单列唯一。基数不明确时登记待核实，不用好看的连线替代依据。

设计图可以表达已确认的设计方案，但题名、图例和正文应让读者知道是方案还是实际实现；同一篇论文中的状态保持一致。复杂图先画主干，细节拆子图或另图并建立对应，不把整张大图缩成不可读的字号。

## 生成前的图表规格

每个图表至少确定：

```text
稳定ID：例如 FIG-001 / TAB-001（内部ID与最终“图3-1”等正式编号分别记录）
题名、用途和章节：回答哪个问题，支持哪个主张
内容：节点/参与者/关系/判断及出口，或表头/数据系列/单位/分母
依据与基线：Evidence编号、源文件位置/SQL/数据/日志、版本与取得状态
形式：图种、布局方向、分组、图例、颜色或线型含义、目标插入尺寸
交付：可编辑源、必要数据/生成脚本、实际导出格式、正文引用位置
核实状态：内容待核/已核、源稿已写、未渲染/已导出、未查看/已查看、未入稿/页面已检查
```

先核语义再排布局。中文正文通常采用中文标签，代码名/数据库字段按论文约定保留。名称和缩写与正文一致；图例解释符号，不用颜色作为唯一编码。减少交叉线，判断边有可理解的标签，避免悬空节点、无意义双向箭头和不清楚的泳道职责。

学校规范决定题注位置、编号规则、字体字号、线宽、图表跨页、表头和表格线样式；不能将某个学校的三线表或“图题在下”等规则当作所有论文的默认要求。未拿到规范时用清晰可改的中性样式，保留格式核对待办。

## 工具与导出路径

先发现当前已有的制图/文档专用工具、相关技能与本地运行库，实际试用最小图再决定路径。当前任务涉及特定应用时按其工具/技能规则使用；不要求所有用户连接同一平台。

| 当前能力 | 可执行路径 | 交付与限制 |
| --- | --- | --- |
| 有可用的制图应用或文档原生图表 | 在指定文件中创建可编辑对象，导出该环境支持的格式 | 保留源文档/图源；检查导出文件及正式稿页面，不把面板可见当导出成功 |
| 有 Mermaid 渲染器 | 为流程、时序、状态或 ER 等图保存 `.mmd` 并实际渲染 | 只用当前版本支持的语法；渲染后逐项复核标签和关系，代码块本身不算已出图 |
| 有 Graphviz 引擎 | 保存 `.dot`，选择支持的 SVG/PNG/PDF 输出 | 核实当前安装支持的格式及中文字体；命令或引擎成功后仍要查看导出图 |
| 有 Matplotlib/R/其他绘图库 | 从真实 CSV/JSON 等数据生成图，保存脚本与导出图 | 保留处理口径及原数据定位；使用可用字体，检查缺字、单位、刻度和数值 |
| 只有文件生成或编辑能力 | 可生成可编辑 SVG，或 `.mmd`/`.dot`、CSV/表格源 | 有条件就实际渲染查看；没有渲染能力时明确交的是源稿，列出尚未检查的项目 |
| 无文件写入/无渲染能力 | 在对话交付完整图源或节点—连线规格、可复制表格和保存步骤 | 不声称文件落盘、图片导出或正式稿页面已验收；需要改变既定交付时说明差距 |

不为流程、关系、数值和测试结果使用生成式图片替代确定性图源；不将重绘的界面当真实截图。需要论文插图或概念示意的生成式视觉时另按对应图像工具规则处理，明确其示意性质。

Graphviz 已可用时，常见导出方式如下；只对当前可信图源和明确输出路径执行，旧导出图先按项目约定留版：

```text
dot -Tsvg "figures/source/FIG-001.dot" -o "figures/export/FIG-001.svg"
dot -Tpng "figures/source/FIG-001.dot" -o "figures/export/FIG-001.png"
```

[Graphviz 命令与格式说明](https://graphviz.org/doc/info/command.html) 和 [输出支持](https://graphviz.org/docs/outputs/)说明实际格式受安装构建影响。[Mermaid 语法](https://mermaid.js.org/syntax/flowchart.html)与[Matplotlib 输出说明](https://matplotlib.org/stable/users/explain/figure/backends.html)按当前工具版本核对。缺少工具时按环境指南发现实际可用选项，再给必要补充及不安装的路径，不在未授权时上传私有图源到在线编辑器。

图源常用 `.mmd/.dot/.drawio/.svg` 或原生文档，数据用 `.csv/.json` 及原始来源索引，生成代码用当前项目实际使用语言。导出格式由学校、编辑器和最终交付决定；优先保留可缩放源/导出，同时按目标环境准备兼容的位图。不能假定所有 Word 版本都支持同一种矢量格式。

## 数据图与表格的口径

- 从真实材料提取或计算数值，保存原始位置、计算方式、筛选、聚合、样本/批次和缺失值处理；不根据希望展示的趋势反推数据。
- 数量比较通常用柱形图，连续且有顺序的时间变化才用折线；不同单位不无说明共用一轴，类别不伪装成连续时间。轴范围与刻度不夸大差异，非零起点等选择在需要时明确说明。
- 失败、阻塞、未执行和缺失分别记录，不改为零失败或通过。通过率/比例说明分母；分母不明确时先给计数并标缺口，零分母不生成无意义百分比。
- 误差线、趋势线、显著性标记和对照组来自真实计算或实验。单批次计数不能变成多次实验、性能曲线或因果结论。
- 图、表、正文及日志数字一致，合计与舍入口径可解释。保留必要精度，不以“美化”改数字、样本或引用。
- 表格保留可编辑单元格、表头、单位和必要注释；跨页重复表头与分页等在正式文档中检查。字段表、测试表只列正文需要的内容，不复制整库或完整敏感记录。

## 三层检查与续写

1. **内容核实：**逐个节点、箭头、判断、状态、表关系和数值回查来源；区分图的设计/实现/观察属性。渲染成功不证明关系正确。
2. **导出查看：**实际打开渲染后的图，检查中文缺字、箭头、分支标签、图例、文字重叠、裁切及空白；必要时调整方向、分组或拆图。只做语法检查不能称已查看。
3. **正式稿页面：**以目标插入尺寸检查可读性和比例，核对题注、正文引用、图表清单及分页；Word/PDF 交付按相应文档技能渲染查看有关页面。图片看起来清晰不能代替文档页面验收。

位图清晰度结合插入尺寸判断：有效像素密度 = 像素宽度 ÷ 插入宽度（英寸）。所需数值以学校/出版方要求为准，不统一硬编码某个 DPI，也不把给低清图改 DPI 元数据当作提升细节。PDF/SVG 中也可能内嵌低清位图，需要看实际内容。

输出保存到已有约定位置；新工作区按 `figures/source/`、`figures/data/`、`figures/export/` 分工，原始界面截图仍放截图材料目录。原生表格可留在权威文档中，索引记录其位置，不强制生成图片。

完成时交付实际图源/数据与导出文件、建议题注和正文引用，并简述已完成的内容核实、导出查看和页面检查。修改图表后同步有关正文、图号、题注、索引与正式稿；未执行部分准确登记，不用“有图片文件”代替验收。
