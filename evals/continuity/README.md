# 大材料与新代理接续试点

本案例独立于十一项基础行为场景及第一批十二次困难写作试点。材料为本轮新合成的社区订货项目，不是用户的业务项目；20个模块用于检查同名文件、跨模块连接和后台入口。题目生成后冻结，运行者仅获得输入与候选规则，评分和变更计划分开保存。合成题仍可能过于简短清晰，不能据此认证真实大型项目的专业深度或跨组织迁移。

## 运行顺序

1. 将 `case/input/` 复制为首轮只读材料，向新代理提供任务和已冻结的候选规则；产物与阅读日志放在材料根外。
2. 模型仅通过 `material_reader.py` 获取项目清单与内容；清单调用 `inventory_sources.py --hash`。规则、任务和已生成产物可直接读取。
3. 保存首轮全部产物和来源快照，检查字节、修改时间和文件集合未被运行者改变。
4. 在另一个材料副本按 `change-plan.json` 唯一套用补丁：修改两个已有源码路径、新增一个模块，共三个源码路径变化。保留V1原始输入。
5. 创建不继承首轮上下文的新代理，只交V2材料、规则、六份正式首轮产物及来源清单，要求继续受影响的章节、图源、测试计划、主张与checkpoint。不给评分、补丁答案、`read-*.json`原文缓存或产物生成脚本；需要原文时仍走统一读取器。
6. 独立代理按原材料和评分条件审查结果；保存实际错误和未决项，不把文件齐全当成业务理解。

`material_reader.py` 的日志记录向代理返回的完整路径、指纹和字节数，正文只返回、不写入日志。哈希扫描另记磁盘读取量。这个约定不是操作系统级隔离，也不能证明代理已经理解每个返回内容；源树前后快照补充只读检查。正文/图源未渲染不算页面验收，测试计划不算业务测试。

本次试点在第5步交接时额外复制了首轮原始阅读JSON。续轮Python加载五个旧缓存包，再向模型显示八份未变源码；当前项目读取器另返回三份变化源码。报告和`read-scope.json`保留这一计量缺口，不把三份包装成全部源码阅读。上面的交接约束是根据此观察修订的复跑方法，本次原始输出没有重写成按新约束执行的结果。

## 复查存档

在仓库根执行：

```text
python -B -m unittest discover -s evals/continuity -p test_*.py -v
python -B evals/continuity/summarize.py evals/continuity/results/pilot-20261029
```

汇总器核验原始产物与评审的指纹、版本材料、清单及阅读日志，分别统计内容返回与磁盘哈希；它不重新运行模型，不自动评分语义，不证明质量增益。结果与限制见 `docs/batch3-validation.md`。开发输入、评分、日志和原始模型产物保留在仓库，不进入日常技能ZIP。
