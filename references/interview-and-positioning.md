# 多轮访谈与论文定位

## 对话节奏

访谈要解决“写什么、凭什么写、怎样完成”。下面三轮是信息层次，不是固定三次对话；先读取现有材料，按实际缺口合并或省去已回答的部分。通常一次 2—3 问。使用当前可用的提问工具或普通对话；提问需要真实用户回答时保持该问题待答，不用时间经过或模型假设代替答案。不要一次贴出几十个问题，也不要对已经明确的信息反复确认。

每轮先简短归纳已知内容，指出还差哪些影响方向的信息。可以给具体可选项并允许自由回答。缺失信息分为决定研究方向的必需项与不影响当前工作的补充项，后者登记后继续。

## 第一轮：想完成什么论文

- 学科/专业、培养层次与论文用途是什么？当前要做选题、开题、初稿、修改还是投稿？
- 已有题目、导师方向或正式目录吗？尚未定题时最感兴趣的对象与问题是什么？
- 学校或导师对研究类型、成果形式、时间和篇幅有哪些明确要求？已有文件直接读取，不凭模板推定。

根据用户负担合并相关问题，时间与格式材料可在第二轮补充。用户不懂研究类型时，用“做一个系统并验证”“用真实数据回答问题”“比较已有研究”等通俗例子解释，不强迫用户先给方法名称。

## 第二轮：有什么材料，实际能做什么

共同问题：哪些材料已经在手、来源在哪里、哪些尚未取得、允许怎样使用、距离交稿还有多久？后续只追问有关分支：

| 候选路径 | 需要核实的材料与条件 |
| --- | --- |
| 软件工程/设计实现 | 有无项目、完成范围、源码/SQL/文档、能否启动、可测试环境；无实现时不能写成完成论文 |
| 调查或数据实证 | 研究对象、数据来源、字段与样本、问卷/访谈是否已执行、可访问的原始记录、可行分析方法 |
| 实验 | 研究变量、方案、设备/材料/数据集、原始记录、实际完成情况及可重复条件 |
| 文献综述 | 具体主题、检索入口与可访问文献、范围、筛选和比较方法；是否真的满足系统综述要求 |
| 理论/文本/案例分析 | 概念、理论或原始文本、案例选择依据、分析框架、论证和反例材料 |

不要默认用户能再做一轮问卷、能访问付费全文、有实验室或有代码。方法与条件不匹配时提出缩小问题、调整方法或补充材料的可行选项。计划调查或计划实验可用于开题与方案，但不能充当已取得结果。

同时按 [environment-and-fallbacks.md](environment-and-fallbacks.md) 自行检查本轮所需工具与目标访问。优先从当前会话发现 MCP/专用工具、可用技能及本机运行条件，已知环境不再让用户手填。区分缺工具、缺授权、缺材料和执行失败，准备推荐、补充与兜底方案；不把可选工具缺少变成额外的强制配置轮次。

## 第三轮：提出定位，让用户选择或修正

材料足以判断时提出一个最可行的方案；存在实质差异时提供 2—3 个方向并说明取舍。不要把多个候选同时定为正式范围。定位草案至少包括：

1. 专业/层次/用途、本轮交付与时间约束。
2. 暂定或正式题目，题目是用户已定还是待选择。
3. 核心研究问题、研究对象、范围与不处理的相关问题。
4. 论文类型与方法，选择理由及可行条件。
5. 已有材料、待取得材料、来源可靠性和关键缺口。
6. 预期成果形式及可支持的结论层级，不能预写希望出现的研究结果。
7. 章节逻辑和建议目录，各节需要的证据。
8. 工作区配置、所需工具和访问能力、缺口与可行兜底、下一步材料任务；正式交付仍缺少必要能力时明确指出。

向用户展示具体定位，让用户回答“按这个方向继续”或提出修改。记录其实际反馈、确认范围和仍待核实的事项；没有明确认可时，状态保持“定位草案”。用户已在当前会话明确指定完整定位时，可直接记录其已有决定，避免再索取相同确认。

## 交接到写作

把访谈摘要放 `intake/interview.md`，定位放 `intake/positioning.md`。不必保存无关隐私或逐字聊天。明确区分用户陈述、文件核实、模型建议与用户已确认的选择。

定位决定路径及所需材料；材料整理完成后再定章节蓝图、写正文。定位确认不等于所有事实已经核实。重要研究条件后来不成立时，说明影响并回到相关定位问题，不静默换题或把计划写成结果。

已有论文续写只检查当前定位与任务是否冲突，不重做全套访谈。用户仅要求本技能的方案、改造或打包时，不启动论文访谈。

只审查或润色一段既有文字，不要求用户先补齐全篇定位、交稿日期或研究条件。先完成与该段有关的读取和检查；只有不确定信息会改变本轮事实或处理方向时才提问。已有文件缺少 `intake/positioning.md` 不等于用户尚未确定题目或方法。
