# 大材料量分析与跨会话接续

本参考用于多模块项目、相似文件名、跨模块调用和后续材料变化。清单回答“当前范围有哪些文件”，模型仍需解释业务主体、入口、状态和连接；文件数量不能作为业务理解或章节覆盖的证明。

## 先划定材料范围，再列文件

使用用户选择的项目或材料根目录。不要把设备根目录、整个用户目录当默认范围。已知另有独立材料目录时，按本轮授权分别列清单，并在接续记录中写清边界。

```text
python -B <skill>/scripts/inventory_sources.py --root "<project>"
python -B <skill>/scripts/inventory_sources.py --root "<project>" --exclude archive/vendor-copy
python -B <skill>/scripts/inventory_sources.py --root "<project>" --hash --hash-mode text-lf
```

脚本只向标准输出写 JSON，不启动项目、不联网、不导入项目代码、不写清单文件或缓存。由调用者按本轮任务需要保存报告。`--root` 必填；`--exclude` 可重复，只能填写所选根目录内的相对目录，不能排除根本身、文件或根外路径。不存在的指定排除目录会作为需核对项报告。

默认按目录名跳过 `.git`、`node_modules`、`.venv`、`venv`、`__pycache__`、`dist`、`build`、`.pytest_cache`、`.mypy_cache`、`.tox`，在任何深度生效。报告列出默认规则和实际排除路径。目录名只是依赖或产物的常见提示，不能证明其内容性质；业务恰好使用这些名称时加 `--no-default-excludes`，再用明确的 `--exclude` 选择无需扫描的目录。`backend`、`jobs`、`workers` 等业务后台目录不会默认排除。

符号链接和 Windows Junction 等重解析点不跟随，并列为跳过项。无法枚举、无法安全核对或读取失败会报告问题，不把未读材料写成已覆盖。输入范围与路径的静态检查不能提供操作系统级隔离，也不能保证材料并发替换时的原子快照。

## 清单结果的含义

默认每项只有完整根内相对路径 `path`、文件字节数 `bytes`、修改时间 `mtime_ns`。选 `--hash` 时增加 `sha256` 和 `hash_mode`；`bytes` 对原始字节计算，`text-lf` 仅把 CRLF 字节序列转为 LF 后计算，不解码文本，也不等于理解内容或忽略所有空白差异。根目录记录为解析后的绝对路径。

报告包含 `files`、`excluded`、`skipped`、`findings` 和 `coverage`。`coverage.files_listed` 是本次已列文件数；`content_hash_attempts`、`content_hash_reads`、`content_hash_bytes` 分别记录尝试指纹、成功读取的文件数和实际成功读取的原始字节总量。失败项保留可用元数据，增加 `hash_status: unreadable`，不伪造指纹。扫描中发现大小或修改时间变化时提示重核基线。

退出码 `0` 表示本次所选枚举范围内未发现问题，`1` 表示存在跳过或需核对项，`2` 表示根目录或选项无效；任何退出码都不能证明整个项目已读懂。`status: listed` 与 `status: partial` 同样只描述清单过程。`--help` 也输出 JSON，使用 `status: usage` 和 `usage` 字段提供帮助。

默认清单不调用文件内容读取；`--hash` 会读取所有未排除且成功打开的文件字节。必须区分元数据枚举、指纹工具的磁盘内容读取、模型为理解业务而读取内容三种活动。`business_modules_assessed` 和 `model_content_reads_measured` 固定为 `false`，脚本不会代替业务审查或统计模型阅读行为。只读承诺针对源文件字节、修改时间和文件集合；操作系统访问时间变化不在保证之内。

## 分批形成业务地图

面对约 20 个模块时，先用清单寻找入口候选，再按业务连接分批读取。每批大小由材料复杂度决定，不固定为文件数。应覆盖公开路由、后台任务注册、权限入口、消息处理和配置连接；不能只按前端菜单推定完整范围。

模块地图至少保留下列信息：

| 项目 | 记录方式 |
| --- | --- |
| 模块或业务主体 | 说明名称及本轮理解的职责，不把目录名直接当成结论 |
| 入口 | 完整相对路径及函数、路由、任务名等可定位符，说明如何注册 |
| 关键连接 | 调用方、被调用方、共享状态或数据表，附相应定位符 |
| 已读材料与基线 | 记录实际为理解而读取的文件和范围；有指纹时注明算法、模式及基线 |
| 理解状态 | 已核实、部分核实、未读候选、排除及理由，不能用“清单中存在”替代已核实 |
| 未决项 | 隐蔽入口、冲突、未取得材料、需运行验证的边界 |
| 论文关联 | 证据或主张 ID、章节段落、图表和测试记录的位置 |

多个 `service.py` 或 `index.ts` 必须使用完整路径区分。一个模块读完后，追踪其关键跨模块连接，不能根据相似命名复制另一个模块的理解。记录本批发现和后续入口，随后才选择下一批。必要时回读相关连接，保留回读理由。

## 接续记录应支持下一会话继续

在论文工作区已有接续位置记录以下信息；可沿用现有文件，不为了格式重新初始化工作区：

1. 当前任务、用户已经确定的论文定位、适用阶段，以及仍需用户决定的问题。
2. 所选材料根目录、清单基线、排除规则和未能枚举的范围。
3. 模块地图、实际内容阅读位置、已核实入口和跨模块连接。
4. 稳定证据或主张 ID、来源版本或指纹、关联正文、图表和测试定位。
5. 当前稿件版本、未决项、下一步最小阅读集合及其理由。

新会话先读这些接续记录及其引用的必要材料。列当前清单，与上次的完整路径集合比较，发现新增、删除、重命名候选和元数据变化。元数据相同不保证内容相同；关键证据应按已登记的指纹或版本核对，必要时明确选择较广的哈希扫描，并记录其磁盘读取量。

对新增入口、已知变化和与本轮论述相关的连接定向读取。未变更且已有充分记录的材料不机械全量重读；若记录不足、来源无法核实或任务改变，说明理由并补读。用户已确认的定位不因换会话重新访谈；只有未决问题和本轮新增决定需要询问。

## 变化提示与重新核实分开

已登记来源与关联位置时，使用现有证据变化检查流程，把变化传播到需复核的正文、流程图和测试说明。指纹变化、路径失效或重命名只说明需要核查，不能直接断言主张错误。未受影响章节的旧结论应保留其有效范围，不据此宣布全稿失效。

复核来源后，按用户指示或本轮已授权任务更新证据、正文及基线，写清新的依据和复核结果。不要在检查后自动刷新指纹，否则会掩盖尚未审查的变化；也不要求把全部旧材料迁移成新格式。

记录每轮原始输出、材料变化、定位成功与漏项。可另记模型实际内容读取的路径、范围及重复原因，和哈希扫描量分开统计。一份合成项目能够验证某些接续行为，不能证明所有真实项目都无遗漏、上下文成本一定下降或其他学科方法已经验证。
