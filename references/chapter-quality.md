# 章节深度：事实正确之后还要解释什么

用于完整章、新节、实质扩写、压缩核心内容和论述充分性审查。已有局部润色不因此重做全章评分。正式目录、学校要求、作者目标及原项目有效规范优先；以下是可选判据，不是统一章节模板。

## 先分开两类判断

**事实判断**回答“材料是否支持这句话”；**深度判断**回答“本节是否把需要的关系解释清楚”。事实全对的功能清单仍可能过浅；机制写得详细也不能抵消错误数字、虚构实现或失实引用。两者分别记录，不用总分互相抵消。

先确定本节的任务、来源和相邻章节分工，再选择适用项。不要求每段机械覆盖全部维度。证据不足且无法判定的项登记为“无法评定”，不适用项注明理由，不能按零分混入可比总分。

| 深度等级 | 可观察判断 |
| --- | --- |
| 0 缺失 | 本节承担的关键问题没有得到解释；定位到应承担该任务的节及相邻原稿，不虚构缺失句的引文 |
| 1 仅提及 | 出现功能、条件、组件或字段名称，但读者仍不能据此复述它们怎样共同完成任务 |
| 2 机制解释充分 | 读者能复述关键条件如何决定处理路径、材料/数据如何变化、结果或失败怎样产生；解释可回查原始依据 |

等级用于定位缺口，不是论文质量认证。不要仅因出现某个词、达到字数或画了图就判“充分”，也不要用所有项目都不适用的统一合格线。

## 软件章节可选的六项关系

| 检查项 | 需要解释的关系 | 常见“只提及” |
| --- | --- | --- |
| 主体与触发 | 谁在何入口、何种情况下发起什么任务 | “系统提供借用功能” |
| 条件与规则 | 哪些身份/归属、输入、状态、重复或名额条件决定是否继续 | “进行合法性校验”而不说明允许条件与拒绝出口 |
| 处理链与分支 | 入口、服务、存储或必要组件怎样衔接，分支为何发生 | 只列类名或逐行翻译源码 |
| 数据与状态变化 | 读写什么，前后状态、关联、事务或消息如何约束结果 | “保存数据并更新状态”而不说明共同提交或失败后的状态 |
| 结果、异常与边界 | 返回什么；拒绝、回退、补偿或未验证部分怎样处理 | 笼统写“保证一致性”“异常处理完善” |
| 依据与章节作用 | 哪份来源支持哪层判断；本节比相邻章节新增什么解释 | 重复需求/设计章，或以代码存在推出实测通过 |

解释真实机制及其与业务约束的关系，通常不需要复述所有内部调用、字段和支线。没有材料证明的设计动机，不能写成作者做过的访谈、比较试验或开发经历。缺失机制先取证，不能靠扩写猜测。

## 按章节职责选项

| 本章任务 | 充分解释通常体现为 | 不能代替它的内容 |
| --- | --- | --- |
| 绪论/相关工作 | 有来源的问题背景、对象与范围、相关工作怎样回应问题及与本项目的关系 | 宏观意义、无界定的“研究空白”、未经阅读的文献罗列 |
| 相关技术 | 实际技术在何业务点发挥作用，与什么协作及采用边界 | 通用教程、依赖名单、配置声明冒充实际运行 |
| 需求分析 | 主体、任务、业务规则、权限/资源边界和跨角色关系；质量目标与验证结果分开 | 页面菜单清单、实现细节代替需求、把目标写成已达成 |
| 系统设计 | 职责、数据关系、状态和约束怎样回应需求，设计与实现/部署属性清楚 | 只列图表、照抄架构术语、按外键命名推断数据库约束 |
| 系统实现 | 真实入口、关键处理链、条件、数据变化、事务及失败边界与设计相对应 | 功能介绍、源码翻译、将注释或旧说明覆盖当前实现 |
| 系统测试 | 环境/版本、方法、前置条件、操作、预期、实际及结论一一对应；批次与单位分开 | 通过数量清单、构建成功、不同版本报告合并成整体通过 |
| 结论与展望 | 按需求、设计、实现和验证总结实际完成工作，由真实缺口推导后续事项 | 再列一次功能、把计划当成果、无依据的性能或效果承诺 |

非软件论文沿实际研究路径使用问题、对象、方法、材料、结果和论证关系，不强加控制器、状态机或数据库判据。通用格式与本指南不能代替统计、实验或学科方法审查；本轮深度对照和困难评测的主要验证范围是软件系统实现章。

## 用原稿定位问题并修改

记录以下信息，可写入已有审查记录，不要求另建一套文件：

```text
检查项与适用理由：本节承担什么问题
原稿定位：文件、节号、稳定段落ID（或序号）及必要短摘录
事实判断：支持 / 冲突 / 证据不足 / 本轮未检查
深度等级：0 / 1 / 2；不适用或无法评定另记
原始依据：文件/方法/表/记录的具体位置与版本
问题及影响：缺哪条关系，读者因而无法判断什么
具体动作：补哪段机制、删哪处重复、保留哪些关键条件和边界
复核：修改后关系是否完整，数字/引用/图表是否受影响
```

短摘录必须确实来自原稿；找不到稳定段落ID时用标题与段落开头定位。缺失项说明“未找到”及检查范围，不造一句示例当成原稿。源码与事实摘要冲突时先回查原材料。

补写先围绕缺失关系组织论述，再删除重复。压缩前后核对主体、条件、关键状态、失败出口及必要限定仍完整；不以简洁为由把复杂核心流程压成一句功能名。表格集中比较，正文解释关系和影响；图有分支时解释主要分支和状态，不能用贴图替代正文。

篇幅只用于提醒可能遗漏的主题，目标由学校与作者决定。不要迁移某个项目的固定章数、技术栈、模块清单或字数区间，也不靠同义改写填长。
