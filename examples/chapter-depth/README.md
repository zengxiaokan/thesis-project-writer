# 教学对照：同样事实，怎样写出实现机制

这是为审查正文深度而编写的**合成设备借还案例**，不是现实项目、真实毕业论文或实际作者材料。两份章节均由同一份合成材料编写，差别是对机制、关系和边界的解释程度，不代表两个系统的实现水平不同。

- [materials.md](materials.md)：原始合成规则、表定义、处理步骤和材料边界。
- [shallow.md](shallow.md)：五节完整的“系统实现”章，各节均有正文，事实正确但若干关键机制只被提到或没有展开。
- [developed.md](developed.md)：相同五节的展开稿，以相同材料说明条件、处理链、字段变化及失败路径。
- [review.md](review.md)：按稳定段落编号引用两稿，区分缺失、仅提及与机制解释充分，并保留两稿均充分的检查项。

每稿的 `P5-xx` 是教学审查用段落编号，不是通用论文排版要求。两稿有意对齐主要主题，展开稿的新增段落使用预留编号，便于定位而不修改浅稿编号。章节编号与结构也仅供本例，不应替代学校和作者的正式目录。

使用时先阅读材料，再比较同一主题的原段落与审查判断。深度不等于字数：展开稿的篇幅仅用于容纳本例已给出的机制；不把它转化为所有章节的字数或段数门槛。若压缩文字，应检查主体、条件、状态变化与失败路径是否仍可复述。

本例没有执行所列 SQL、借还操作、自动化测试、并发实验或部署。材料中的处理步骤描述的是合成实现约定。两稿都不能据此宣称用例通过、系统稳定、生产可用或效率提高。

此对照是教学材料和审查样例，**不是模型效果评测结果**；它不能证明技能优于基线，也不应作为运行代理可见的困难评测标准答案。真实评测需另用原始输入、分离评分条件并保留实际输出。
