# 0.5.0 第二批：只读检查验证

日期：2026-10-29。本批实现两个可选检查器及合成小样稿。本轮没有修改已安装技能或正式论文，也没有开展新的模型写作效果比较；第一批十二次试运行“未显示相对增益”的结论不因本轮脚本通过而改变。

## 已交付的能力与边界

| 工具 | 实际检查 | 结果含义 |
| --- | --- | --- |
| [一致性检查](../references/consistency-checks.md) | 显式ID及引用、可解析本地图片路径、已登记带类型表格的合计与同口径比较、待确认标记、已登记目录及权威稿指纹 | 给出问题位置、已查范围与跳过项；不判定普通自然语言数字、文献支持、机制或页面是否正确 |
| [证据变更提示](../references/evidence-changes.md) | 稳定主张ID的已登记来源指纹、关联位置、来源失效与限定范围内同指纹候选 | 只提示有关主张/正文/图表/测试需复核；不宣判主张错误、不全篇失效、不采用候选或刷新基线 |

两个CLI均使用标准库，仅向标准输出交付JSON，不联网、不导入执行待查项目、不写被查材料、登记或缓存。脚本没有自动修复、覆盖权威稿或接受新基线的功能。旧稿可选定Markdown做基础检查，需要时再映射现有记录；缺配置和不支持的范围不算通过。

## 实际复跑

[小样稿](../examples/readonly-checks/README.md)全部为合成文本、来源片段、图源及人为计数，不是现实项目或真实测试记录。[原始观察](../examples/readonly-checks/observation.json)保存工具源码指纹、运行环境、实际发现与定位。

在临时副本中植入并实际检出的九类问题为：重复ID、预期ID缺失、悬空引用、本地缺图、待确认标记、目录缺项、表格合计错误、同口径数字冲突和权威稿指纹变化。正常对照零发现，历史批次/版本/对象/方法/单位的正常差异没有误判为冲突，代码块中的示例也没有计入正文。

状态判断来源变更后，只将 C-STATE 标记为需复核，具体关联到：

| 类型 | 位置 |
| --- | --- |
| 正文 | chapters/chapter-5.md，5.1 |
| 图源 | figures/source/FIG-501.mmd，FIG-501 |
| 测试说明 | tests/plan.md，状态条件 |

C-CATALOG 的已登记来源没有检测到变化。另一个副本将目录来源重命名后，原路径仍报告失效，新文件仅作为唯一同指纹候选显示，登记没有被修改。来源未变只针对登记指纹，不证明有关正文语义正确。

每次审查调用前后比较全部被查文件的字节、修改时间和文件清单，结果均未变化，原始base小样稿也未变化。操作系统访问时间不在该保证内，路径检查也不是持续并发敌意替换下的原子读取隔离。

## 检查与审查记录

本机 Windows Python 3.14.6 和独立的 Python 3.8.10 运行时各执行72项检查，均为71项通过、1项目录符号链接用例因系统权限跳过；Windows Junction 用例实际执行。原始材料评测的6项维护检查另行通过，未重做第一批模型写作运行。跨平台结果以 [CI对应提交](https://github.com/zengxiaokan/thesis-project-writer/actions)为准。

新增覆盖包括：不同数字口径/比较身份不混并、空值或混合单位不作零、明确Decimal容差、大整数不被默认精度舍入、权威稿存在/缺基线/变化、未配置及空范围、基线缺失、源缺失、唯一/多候选/不搜索、文本和字节换行模式、输入结构、安全路径及只读行为。

独立代码审查后补齐严格版本类型、旧解释器路径环错误、合法带括号图片路径等边界，并以实际用例复核。发行链接检查复用同一目标解析规则，避免把代码示例或尖括号路径当成失效链接，同时保留真实坏链接的拒绝验证。

程序检查不证明语义、图像清晰度、Word页面或全篇质量已验收。文献综合、约二十模块的大材料和跨会话接续验证仍属于第三批。
